This guide is written like a mentor's checklist. Work through it in order.

## 2. Prepare the folder before you upload

Run these checks from the project folder:

```bash
python tests/run_tests.py          # all tests must pass
python main.py                     # final outputs regenerated
```

Remove files that should not be public:

```bash
rm -rf __pycache__ */__pycache__ .pytest_cache    # Windows: rmdir /s /q
rm -f models/*.joblib                             # ignored anyway, but tidy
```

Check the folder contains: `README.md`, `requirements.txt`, `.gitignore`, `main.py`, `config.py`, `src/`, `app/`, `tests/`, `docs/`, `data/raw/`, `outputs/`, `images/`, `reports/`.

---

## 3. Create the repository on GitHub

1. Log in to github.com and click **+** → **New repository**.
2. Enter the name and description from section 1.
3. Select **Public**.
4. **Do not** tick "Add a README", ".gitignore" or "license". You already have them.
5. Click **Create repository**. Keep the page open; you will need its URL.

---

## 4. Connect your local folder and push

Install Git first if needed (`git --version` should print a version).

**Mac / Linux**

```bash
cd Retail-Sales-Forecasting-Inventory-Optimization
git init
git branch -M main
git add .
git status                          # check: no .venv, no __pycache__, no joblib
git commit -m "feat: initial end-to-end forecasting and inventory pipeline"
git remote add origin https://github.com/YOUR-USERNAME/retail-sales-forecasting-inventory-optimization.git
git push -u origin main
```

**Windows (PowerShell)**

```powershell
cd Retail-Sales-Forecasting-Inventory-Optimization
git init
git branch -M main
git add .
git status
git commit -m "feat: initial end-to-end forecasting and inventory pipeline"
git remote add origin https://github.com/YOUR-USERNAME/retail-sales-forecasting-inventory-optimization.git
git push -u origin main
```

When Git asks for a password, use a **Personal Access Token**, not your GitHub password. Create one at GitHub → Settings → Developer settings → Personal access tokens. See [TROUBLESHOOTING.md](TROUBLESHOOTING.md) if the push fails.

## 5. Commit messages that recruiters notice

Use a short type prefix and a clear message. Recruiters scan commit history, so each message should say what changed and why.

| Good | Weak |
|---|---|
| `feat: add synthetic retail sales simulator with stockouts` | `update` |
| `fix: keep stockout days out of training target` | `fix bug` |
| `feat: add rolling-origin backtest with MAE, RMSE, MASE, WAPE` | `changes` |
| `docs: explain safety stock and reorder point with worked example` | `readme` |

Prefixes: `feat` (new feature), `fix` (bug fix), `docs` (documentation), `test` (tests), `refactor` (tidy code, same behaviour), `chore` (housekeeping).

## 6. Uploading screenshots and the demo

1. Most proof images are already in `images/screenshots/`, generated by `python scripts/make_screenshots.py`. Capture only the three manual ones by hand: `04_dashboard.png` (run the dashboard), `06_github_repo.png` and `07_readme_preview.png` (after upload). The index is in `images/screenshots/README.md`.
2. Commit them: `git add images/screenshots && git commit -m "docs: add dashboard, repository and README screenshots"`.
3. In `README.md`, remove the `<!--` and `-->` around the dashboard line in the Charts section.
4. For a GIF or video: put the GIF in `docs/demo.gif` and add `![Demo](docs/demo.gif)` near the top of the README, or link a YouTube video.
5. Commit and push. Check the README on GitHub, because relative image paths only work if the file name and capital letters match exactly.

## 8. Eight-day proof plan

Spread the work over eight days. Each day produces commits, proof and notes for your CV.

| Day | Work | Commit message | Proof to save | Note for CV/LinkedIn |
|---|---|---|---|---|
| 1 | Set up the project folder, environment and config | `chore: project structure and config` | Screenshot of the folder tree | "Designed a modular project structure" |
| 2 | Simulate dataset and clean it | `feat: synthetic retail simulator and data quality checks` | Dataset preview, data quality report | "Built a simulator with stockouts and promotions" |
| 3 | EDA and trend analysis | `feat: EDA charts for trend, seasonality and promotions` | Sales trend, weekday and intermittency charts | "Found weekend, summer and festive patterns" |
| 4 | Feature engineering with leakage tests | `feat: lag, rolling and calendar features with leakage test` | Feature code snippet, passing test output | "Prevented data leakage with automated tests" |
| 5 | Forecasting models and backtests | `feat: hybrid forecast with rolling-origin backtest` | Model comparison chart, metrics table | "Cut forecast error from 52% to 37% WAPE vs naive" |
| 6 | Inventory policy | `feat: safety stock, reorder point and EOQ policy` | Reorder alerts chart, worked example | "Calculated reorder points and order quantities" |
| 7 | Dashboard and final visuals | `feat: streamlit dashboard with CSV export` | Dashboard screenshot, GIF | "Built a planner dashboard with CSV export" |
| 8 | Documentation and upload | `docs: complete README, guides and screenshots` | Repo screenshot, README preview | "Published a documented, tested project on GitHub" |

**Rule for every day:** commit at least once, save one screenshot, and write two sentences in your notes file about what you built and why it matters.

## 9. Recruiter-friendly README checklist

Before you share the link, confirm the README:

- [ ] states the problem in one plain sentence at the top
- [ ] shows results in numbers near the top (done in this README)
- [ ] says the data is synthetic, clearly and early
- [ ] has a working install and run section, copy-paste ready
- [ ] shows at least three charts that render on GitHub
- [ ] explains the business value in terms of stock-outs and cash
- [ ] has a limitations section (honesty reads as maturity)
- [ ] has your name, course and contact links filled in
